# ADR-001: Polling vs WebSocket для обновления карты диспетчера

**Статус:** Утвержден

## 1. Контекст

Диспетчеру нужно видеть обновления позиций курьеров на карте. Допустимая задержка — до 1 минуты. Нужно выбрать механизм доставки обновлений.

## 2. Рассмотренные варианты

| Критерий | Polling (5 сек) | WebSocket | SSE |
|----------|----------------|-----------|-----|
| Сложность реализации | Низкая | Высокая | Средняя |
| Инфраструктура | Стандартный HTTP | Sticky sessions, отдельные серверы | HTTP, но persistent connections |
| Latency | 0-5 сек | Sub-second | Sub-second |
| Достаточно для SLA < 1 мин | Да | Да (избыточно) | Да (избыточно) |
| Масштабирование | Stateless, просто | Stateful, сложно | Stateful, средне |

## 3. Решение

**Polling каждые 5 секунд.** Требование staleness < 1 мин выполняется с большим запасом. WebSocket даёт sub-second latency, который не нужен для данного use case. Polling проще в реализации, не требует управления соединениями, sticky sessions, обработки reconnect.

## 4. Последствия

- Чуть больше трафика по сравнению с push-моделью (пустые ответы при отсутствии изменений)
- Простота масштабирования — stateless HTTP
- Если в будущем потребуется sub-second latency (например, для клиентского приложения), нужно будет пересмотреть решение
