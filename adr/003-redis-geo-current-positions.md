# ADR-003: Redis Geo для текущих позиций курьеров

**Статус:** Утвержден

## 1. Контекст

Диспетчеры запрашивают текущие позиции курьеров в bounding box (polling каждые 5 сек, ~1k RPS). Позиции обновляются с частотой 20k updates/sec. Нужно хранилище, которое выдержит высокую частоту обновлений и эффективно отвечает на geo-запросы.

## 2. Рассмотренные варианты

| Критерий | PostgreSQL + B-tree | PostgreSQL + PostGIS | Redis Geo |
|----------|-------------------|---------------------|-----------|
| 20k UPDATE/sec | Тяжело (инвалидация индексов) | Ещё тяжелее (spatial-индекс дороже) | Легко (in-memory) |
| Geo-запросы | 4 условия в WHERE, неоптимально | Нативные, эффективные | GEOSEARCH из коробки |
| Персистентность | Да | Да | Нет (но данные восстановимы из Kafka) |
| Сложность | Низкая | Средняя | Низкая |

## 3. Решение

**Redis Geo.** Текущие позиции — эфемерные данные, которые обновляются каждые 10 сек. Персистентность не нужна — при падении Redis позиции восстанавливаются из потока Kafka за секунды. GEOADD/GEOSEARCH покрывают все use cases карты.

## 4. Последствия

- Redis становится критическим компонентом для карты — нужен Redis Sentinel или Cluster для отказоустойчивости
- При рестарте Redis — кратковременная потеря данных карты (восстановление из Kafka)
- PostgreSQL в couriers сервисе разгружается от 20k UPDATE/sec
